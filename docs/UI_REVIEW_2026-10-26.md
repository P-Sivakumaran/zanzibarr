# UI refinement and review — 26 October 2026

This is a working UI candidate, not a release. The root version remains
1.27.0+28; existing edition, catalogue, legal and stack work is preserved.

## Audit and delivery plan

Used design critique, design system, accessibility, UX copy and Figma
design-to-code guidance. Re-read the actual
[Minimalist frame](https://www.figma.com/design/rTvTd3yopeT26JEmVneFYU?node-id=103-746)
through Figma MCP, including its render and component context. Material buttons
and icon buttons map to the existing Flutter Material widgets. This iteration
adapts the established structure rather than implementing the visual-mode
chooser as another feature.

| Finding | Implemented response |
| --- | --- |
| Default seeded surfaces tint large cards brown, competing with artwork | Neutral navy/charcoal surfaces and off-white light surfaces, explicit text roles and subtle borders |
| Small headings and similar-weight controls weaken hierarchy | Stronger heading weights, 48 logical-pixel button minimums, a filled primary action and quieter secondary actions |
| Library is an unlabelled header icon; playlists require scanning Home | Labelled Library and Playlists destinations on wide layouts; existing compact menu/body access retained |
| Branding and body edges drift on wide screens | Header follows the same 1320-pixel content boundary as Home and uses an opaque surface |
| Settings is a flat collection of ten cards | Viewing, Playback services, Optional connections, About & privacy; two columns when space/text size permit, one column otherwise |
| Screenshot harness duplicates an increasingly stale theme | `AppTheme` supplies both the real app and the screenshot harness |
| Menus, dialogs, tooltips and inputs inherit inconsistent surfaces | Shared explicit surface/foreground roles and consistent shapes/focus styles |
| Matched history rows still show release filenames | Use a saved title identity and episode label when available; exact release identity and playhead remain unchanged |
| Successful series loading can still display a metadata failure | Fixed four state callbacks that returned assigned Futures; the render regression now checks successful title/episode loading |

## Visual contract

- Surface: dark `#111518`, light `#FAFAF8`; cards/menus dark `#1B2126`, light white.
- Main text: dark `#F0F2F4`, light `#20272C`; supporting text `#B6C0C8` / `#52616B`.
- Brand seed remains `#FF453A`; high-emphasis buttons use neutral inverse colours.
- Error roles stay amber to distinguish errors from the red brand. Light error
  foreground was darkened to `#8C4A00`.
- Controls use 12-pixel radii, cards 16; focus borders are 2 pixels. Body line
  heights are 1.45–1.5. Existing wordmark typography and logo are preserved.
- Material defaults for hover/disabled states remain available; focus overrides
  resolve only for focused controls. No new decorative animation was added.
- Existing reduced-motion behaviour, language support, source attribution,
  spoiler controls and confirmed release identity are preserved.

## Review artifacts

`http://localhost:8766` serves only `dist/ui-review/gallery`, bound to loopback.
It offers 16 real Flutter renders: Home, Library, Series details and Settings,
each at 1440 and 390 logical pixels, in dark and light themes. It includes a
Home comparison with an older fixture/viewport, explicitly labelled as such.
It is an image gallery, not a web playback implementation.

The separate native entrypoint `lib/main_ui_review.dart` requires
`--dart-define=UI_REVIEW=true`. Its screen/theme selector and scrolling operate
over read-only production widgets. Form/service/playback actions cannot run;
keyboard focus cannot enter those controls. No native engine bootstrap,
integration startup, update check or account read is performed. Data stores,
metadata, artwork and artwork preferences are local fixtures. Fictional sample
ratings are explicitly attributed to sample data. Artwork comes from the user's
Figma file, never an automatic match to a real film.

Native output: `dist/ui-review/app/zanzibarr-ui-review.exe` with its complete
adjacent bundle and `review-art` folder. No installation, release/version bump,
commit, push or publication is part of this iteration. Existing running apps
are preserved. Native rendering is not claimed verified merely from a build.

Regenerate the gallery in PowerShell:

```powershell
$env:UI_REVIEW_SHOTS='1'
flutter test --no-pub test/ui_professionalization_test.dart --update-goldens
python tools/ui_review_gallery.py
python -m http.server 8766 --bind 127.0.0.1 --directory dist/ui-review/gallery
```

## Verification and limits

Ordered gate passed: 290 Rust tests, Clippy with warnings denied, Flutter
analysis, native host build, then 573 Flutter tests with 10 opt-in skips.
After the final preview isolation/scrolling changes, Flutter analysis and the
complete Flutter suite were rerun: 574 passed, 10 skipped. The focused review
suite has 21 cases, including real production layouts, palette/menu/focus
contrast, keyboard Settings navigation, 200% text with RTL, successful episode
loading and read-only preview scrolling/action suppression. Whitespace checks
pass. Logs are under `dist/audit/ui-review/`.

Contrast checks cover the defined normal text pairs (4.5:1) and focus/control
outlines (3:1), not every pixel in every screen. Screenshots were visually
inspected and corrected. This is not a full accessibility certification:
screen-reader use, physical TV remote input, native player overlays and
device-specific rendering remain separate manual checks. Live metadata,
trailers, release discovery and playback were not exercised with user accounts.

Clean's closed catalogue/composition is intentionally untouched. Shared
production styling applies to the existing main/Restricted application graph;
this does not open any Clean capability. More substantial AI form structure,
player overlay revisions and additional catalogue behaviour should be reviewed
as separate slices after feedback on this visual contract.
